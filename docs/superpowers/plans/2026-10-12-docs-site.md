# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Parts: **1** (this file: header, Task 1) · [2: Tasks 2–3, Home and API Reference](2026-10-12-docs-site-part2.md) · [3: Tasks 4–5](2026-10-12-docs-site-part3.md)

**Goal:** A VitePress site with three areas (Home, Documentation, API Reference), generated from the repo's Markdown and deployed on Cloudflare Pages.

**Architecture:** VitePress uses `docs/` as its root. Existing guides become pages as they are. Sections of the README are reused through region includes, and a new `docs/api-reference*.md` becomes the single source of the API contract. The only test is the build itself, which fails on dead links, plus `grep` checks run on the built HTML.

**Tech Stack:** VitePress 1.6.x (devDependency of the root `package.json`), Cloudflare Pages Git integration.

**Spec:** `docs/superpowers/specs/2026-10-12-docs-site-design.md`

## Global Constraints

- Every Markdown file stays under 200 lines (`CLAUDE.md`).
- Site content is English only.
- No page content exists only for the site: the README and `docs/*.md` are the sources.
- The Worker keeps zero runtime dependencies. `vitepress` goes in `devDependencies` only.
- Never set `ignoreDeadLinks`.
- `srcExclude`: `superpowers/**`, `handoff/**`, `requirements/**`.
- Statuses are `accepted`, `queued`, `processing`, `submitted`, `failed`, `retrying`. Never write "delivered".
- GitHub repo URL: `https://github.com/yintong-zhou/notify-flow`.
- `npm test` and `npm run typecheck` must keep passing.

## Review Focus

1. **Template placeholders written in inline code** (`` `{{name}}` `` in `web-app-integration-flows.md:70`, `ai-integration-prompt.md:55`, README:135) are compiled by Vue as interpolations and render empty. Expected: the literal `{{name}}` is shown. Pinned in Task 1, Step 5.
2. **A wrong region name or include path** renders nothing and still builds without error. Expected: every included README region shows up on its page. Pinned in Task 1, Step 5 and Task 2, Step 3 by grepping the built HTML for a phrase from each region.
3. **Internal docs leak:** specs, plans and handoffs get published if `srcExclude` is wrong. Expected: none of them is in `dist`. Pinned in Task 1, Step 5.
4. **README links break on GitHub:** VitePress never checks the README, so after the edits in Task 4 a relative link can point to a file that does not exist. Expected: every relative README link resolves. Pinned in Task 4, Step 5.
5. **API Reference drifts from the code:** an error code thrown in `src/` is missing from the table, or the table lists a code that no longer exists. Expected: the two sets are equal. Pinned in Task 3, Step 5.

### Task 1: VitePress scaffold, Documentation section, README regions

**Files:** `package.json`, `.gitignore`, `docs/.vitepress/config.mts`, `docs/.vitepress/theme/index.ts`, `docs/.vitepress/theme/style.css`, `docs/getting-started.md`, `README.md` (region markers only), `docs/web-app-integration.md:3`

**Interfaces:**
- Produces: the README regions `why`, `how-it-works`, `getting-started`, `smtp-configuration` and `security`, used by Tasks 1–2; `sidebar` and `nav` in `config.mts`, which Task 3 extends; the `docs:dev`, `docs:build` and `docs:preview` scripts.

- [ ] **Step 1: Install.** Run `npm install -D vitepress@^1.6.4`, then `npm test`. Expected: tests still pass. VitePress brings Vite 5 and npm nests it next to vitest's Vite.

- [ ] **Step 2: Scripts and ignores.** Add to the `scripts` in `package.json`:

```json
"docs:dev": "vitepress dev docs",
"docs:build": "vitepress build docs",
"docs:preview": "vitepress preview docs"
```

Then append `docs/.vitepress/dist/` and `docs/.vitepress/cache/` to `.gitignore`.

- [ ] **Step 3: README regions.** Each marker wraps the section **body only**, without its `##` heading, so every page picks its own headings. Example for "Why":

```md
## Why

<!-- #region why -->
Every app ends up sending the same emails: …
- **Any SMTP provider.** …
<!-- #endregion why -->
```

Add the same pair around the bodies of "How it works" (`how-it-works`), "Getting started" (`getting-started`), "SMTP configuration" (`smtp-configuration`) and "Security" (`security`). GitHub does not render these comments.

- [ ] **Step 4: Config, theme, page.** Create `docs/.vitepress/config.mts`:

```ts
import { defineConfig } from "vitepress";

export default defineConfig({
  title: "notify-flow",
  description: "Self-hosted transactional email for Cloudflare Workers, over plain SMTP",
  cleanUrls: true,
  srcExclude: ["superpowers/**", "handoff/**", "requirements/**"],
  markdown: {
    // Template placeholders like `{{name}}` in inline code must stay literal, not become Vue interpolations.
    config: (md) => {
      const render = md.renderer.rules.code_inline!;
      md.renderer.rules.code_inline = (...args) => render(...args).replace("<code", "<code v-pre");
    },
  },
  themeConfig: {
    nav: [
      { text: "Home", link: "/" },
      { text: "Documentation", link: "/getting-started", activeMatch: "^/(getting-started|web-app-integration|ai-integration)" },
    ],
    sidebar: [
      {
        text: "Documentation",
        items: [
          { text: "Getting started", link: "/getting-started" },
          {
            text: "Integration guide",
            link: "/web-app-integration",
            items: [
              { text: "Flows and production", link: "/web-app-integration-flows" },
              { text: "Asynchronous sending", link: "/web-app-integration-async" },
              { text: "Event-based sending", link: "/web-app-integration-events" },
            ],
          },
          { text: "AI integration prompt", link: "/ai-integration-prompt" },
        ],
      },
    ],
    socialLinks: [{ icon: "github", link: "https://github.com/yintong-zhou/notify-flow" }],
    search: { provider: "local" },
  },
});
```
