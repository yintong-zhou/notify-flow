# Web Push Notifications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** opt-in Web Push per client. A platform backend registers its users' browser subscriptions and calls `POST /v1/push/send`. notify-flow renders a built-in push template, encrypts it, signs it with VAPID and posts it to each device's push service.

**Architecture:**
- **`src/push/`:** everything push lives here, mirroring `src/admin/`:
  - `crypto.ts`: base64url, RFC 8291 encryption, RFC 8292 VAPID;
  - `templates.ts`: built-in templates;
  - `validation.ts`: request parsers;
  - `subscriptions.ts`: D1 subscription store;
  - `sender.ts`: send flow and purge;
  - `routes.ts`: `/v1/push/*` table, gates and handlers.
- **`src/index.ts`:** routes `/v1/push/` to `handlePush`, with `PUSH_RATE_LIMITER` in place of `CLIENT_RATE_LIMITER`.
- **Admin:** two routes, `GET clients` and `POST client-push`, and a Clients panel.

**Tech Stack:** TypeScript on Cloudflare Workers, D1, WebCrypto, and vitest in workerd (`@cloudflare/vitest-plugin`). No runtime dependencies.

**Spec:** [`2026-10-25-web-push-design.md`](../specs/2026-10-25-web-push-design.md) and [part 2](../specs/2026-10-25-web-push-design-part2.md). Read both before starting a task.

**Parts:**

## Global Constraints

- **No runtime dependencies:** WebCrypto only. `vi.mock` does not work in the Workers pool, so inject the push HTTP function (`PushFetch`) and override env bindings with `{ ...env, … }`.
- **Allowlisted push hosts:** `fcm.googleapis.com`, `push.services.mozilla.com`, `notify.windows.com`, `push.apple.com`. A hostname matches if it equals one, or ends with `.` plus one.
- **Input limits:**
  - **`user_id`:** 1-128 characters, no control characters (`/[\u0000-\u001f\u007f]/`).
  - **`endpoint`:** at most 2048 characters, `https:`, empty `port`, no username or password.
  - **`p256dh`:** base64url that decodes to 65 bytes with first byte `0x04`.
  - **`auth`:** base64url that decodes to 16 bytes.
  - **`template`:** `^[a-z0-9-]{1,64}$`.
  - **`locale`:** `it`, `en` or `pt-BR`, default `en`, falling back to `en`.
  - **variable values:** 1-64 characters, no control characters.
  - **`url`:** 1-512 characters, starts with `/`, not `//`, no `\`, no control characters.
  - **`tag`:** `^[A-Za-z0-9_-]{1,32}$`.
- **Per-user cap:** the 10 newest subscriptions per client and user, ordered by `created_at DESC, rowid DESC`.
- **Push request headers:**
  - `TTL: 86400`
  - `Urgency: high`
  - `Topic: <tag>` (only when a tag is given)
  - `Content-Encoding: aes128gcm`
  - `Content-Type: application/octet-stream`
  - `Authorization: vapid t=<jwt>, k=<VAPID_PUBLIC_KEY>`
- **JWT:** header `{"typ":"JWT","alg":"ES256"}`, claims `{aud: <endpoint origin>, exp: <now s> + 43200, sub: VAPID_SUBJECT}`.
- **Retries:** at most 3 attempts, with `500` then `1000` ms backoff. Each attempt has a 5 s timeout (`AbortSignal.timeout(5000)`). These are transient: 429, 5xx, a thrown fetch or a timeout. 404 and 410 mean the subscription is gone. Any other non-2xx is permanent.
- **Limits:**
  - `PUSH_LIMIT_PER_HOUR`: default `"60"`, per client, user and conversation. Same `tag`, or both untagged with the same `template`. Failed rows don't count.
  - `PUSH_RATE_LIMITER`: 600 per 60 s, `namespace_id` `"1005"`.
  - `IP_RATE_LIMITER`: raised to 600.
- **Error codes:**
  - `503 push_not_configured` and `403 push_disabled`. `DELETE /v1/push/subscriptions` is exempt from both.
  - `400 unsupported_push_service`.
  - `404 template_not_found`.
  - `404 no_subscriptions`: with `{id}` once a row exists.
  - `502 push_failed` with `{id}`.
  - `429 rate_limited`.
  - From `POST /admin/api/client-push`: `409 push_not_configured`, `404 not_found`.
- **Statuses** (`push_deliveries`): `processing`, `submitted`, `failed`. The `error_code` values are `push_expired`, `push_failed` and `abandoned`.
- **No content stored or logged:** variable values, the rendered title and body, `url` and `endpoint` never reach `push_deliveries` or `app_logs`. Failed attempts log warn `push_attempt_failed` with `client_id`, `message_id` and detail `HTTP <status> attempt <n>/3` or `network attempt <n>/3`.
- **Config:** `VAPID_PUBLIC_KEY` and `VAPID_SUBJECT` are `vars`, empty by default. `VAPID_PRIVATE_KEY` is a secret, and it is **not** in `secrets.required`. Every config change goes in both `wrangler.jsonc.example` and the local `wrangler.jsonc`.
- **Markdown:** every `.md` file stays under 200 lines.
- **Commands:**
  - one test file: `npx vitest run test/<file>`;
  - all tests: `npm test`;
  - types: `npm run typecheck`;
  - docs: `npm run docs:build`.

## Review Focus

Inputs and failure modes the spec implies but its test list does not pin. Each has a test in its owning task.

1. **The same endpoint registered by two clients** gives two independent rows. A `DELETE` by one client leaves the other's row. Task 2.
2. **Malformed nested bodies** answer `400`, never `500`: `subscription: null`, `keys: "x"`, `variables: null`, `variables: {"sender": 5}`, `url: 5`. Tasks 2 and 3.
3. **Non-ASCII variable values** (`"Zoë 🙂"`) arrive intact in the decrypted payload. The payload's keys are exactly `title`, `body`, plus `url` and `tag` when given. Task 3.
4. **A push service that never answers:** a fetch rejecting with a `TimeoutError` counts as transient. Three attempts are made, then the call ends with `502 push_failed`. Task 3.
5. **Routing:** `GET /v1/push/nope` answers `404 not_found`, and `GET /v1/push/subscriptions` answers `405`. Both come before the push gates, so even a disabled client gets them. Task 2.

## Shared interfaces

```ts
// src/push/crypto.ts
export const b64url: { encode(bytes: Uint8Array): string; decode(text: string): Uint8Array }; // decode throws on bad input
export function importPrivateKey(d: Uint8Array, publicRaw: Uint8Array, use: "ECDH" | "ECDSA"): Promise<CryptoKey>;
export interface Ephemeral { privateKey: CryptoKey; publicRaw: Uint8Array; salt: Uint8Array }
export function deriveKeys(ecdhSecret: Uint8Array, auth: Uint8Array, uaPublic: Uint8Array, asPublic: Uint8Array, salt: Uint8Array): Promise<{ cek: Uint8Array; nonce: Uint8Array }>;
export function encryptPayload(plaintext: Uint8Array, p256dh: Uint8Array, auth: Uint8Array, ephemeral?: Ephemeral): Promise<Uint8Array>;
export interface VapidKeys { publicKey: string; privateKey: string; subject: string } // base64url keys
export function vapidAuthorization(endpoint: string, keys: VapidKeys, nowMs?: number): Promise<string>;
export function vapidKeys(env: Env): VapidKeys | null; // Task 2; null when any of the three is empty
export const pushConfigured: (env: Env) => boolean;  // Task 2

// src/push/subscriptions.ts
export interface Subscription { endpoint: string; p256dh: string; auth: string }
export function upsertSubscription(db: D1Database, clientId: string, userId: string, sub: Subscription): Promise<void>;
export function removeSubscriptions(db: D1Database, clientId: string, target: { endpoint: string } | { userId: string }): Promise<void>;
export function listSubscriptions(db: D1Database, clientId: string, userId: string): Promise<Subscription[]>;
export function deleteSubscription(db: D1Database, clientId: string, endpoint: string): Promise<void>;

// src/push/routes.ts
export type PushFetch = (url: string, init: RequestInit) => Promise<Response>; // sender.ts imports it with `import type`
export function handlePush(req: Request, env: Env, clientId: string, route: string, fetchPush: PushFetch, ctx?: ExecutionContext): Promise<Response>;

// src/push/sender.ts
export interface PushRequest { userId: string; template: string; locale: Locale; variables: Record<string, string>; url?: string; tag?: string }
export interface PushResult { id: string; status: "processing" | "submitted" | "failed"; devices: number }
export function sendPush(env: Env, clientId: string, request: PushRequest, options: SendOptions, fetchPush: PushFetch): Promise<PushResult>;
export function purgePushDeliveries(db: D1Database): Promise<void>;
```
